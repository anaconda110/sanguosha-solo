# 事件驱动技能系统 + 纯函数状态推进

规则引擎采用两个绑定决策（2026-10-05）：(1) 引擎在固定时序点广播事件，武将技能作为事件订阅者介入或修改流程——不把技能硬编码进主流程，也不自创声明式 DSL；(2) 引擎核心为 `step(state, action) → 新状态` 的纯函数推进，状态可整体快照克隆，所有变更经事件日志记录。选事件驱动是因为"加一个武将必须只增不改"，否则技能数量增长会让主流程腐化；选纯函数推进是因为搜索型 AI 需要从任意状态低成本推演（克隆 + 模拟），而可变状态里隐藏的 UI/随机数依赖届时返工成本极高。事件日志同时免费提供回放能力。

## Consequences

- 随机数必须受控（种子纳入状态），否则快照不可复现——AI 模拟与回放都依赖这一点。
- 时序点清单是引擎的核心 API 面；新技能类型可能催生新时序点，属于引擎的正常演进。
