# M15：可玩性批二——存档续局、观战模式、种子输入、回放跳转

M11–M14 补规则与 AI 之后，界面层剩下的三处让"玩起来别扭"的地方一次性补齐
（2026-10-06 定）。

1. **存档续局（persist.ts）**：引擎状态是纯数据（ADR-0002 的副产品），
   `GameState` 可直接 `JSON.stringify` 进 localStorage——不需要任何自定义编码
   （实测：整局终局状态约 27KB，中盘 ~14KB，远低于 5MB 配额）。存档含
   seed / humanId / spectate / 完整 state；**每次状态推进后写一次**，终局时清档
   （已结束的局没有续的必要）。配额超限时自动退化为"只留最近 300 条战报"再存
   ——战报只供显示，动作日志才是续局与回放的依据，因此截断不影响正确性。
2. **观战模式**：`humanId = -1` 表示无真人座次，五家全由 AI 应答（`scheduleAi`
   的"等真人操作"门禁被 spectate 短路）。环形桌位改为固定五方位（自己也在环上），
   提示条显示"某某正在做某事"。这是调试 AI 行为最直观的窗口。
3. **种子输入**：header 的 seed 从只读文本变成输入框 + "按此种子开局"。同种子 +
   同操作 = 同结局（ADR-0002/0005 早有的能力），此前只能靠脚本复现，现在页面
   上就能重放特定局面。
4. **回放跳转**：回放条加 range + 数字框，可拖到任意时刻。实现仍是
   `setup(seed)` + 重演 k 个动作（ADR-0005 的原方案），**不引入快照**——回放是
   终局后的静态检视，O(步数) 的重演代价（最快 190 步的局）完全可接受；引入
   快照会让"动作日志即唯一真相"这一性质失效，代价大于收益。

## 已知简化（记录在案）

- 存档只有一个槽位（覆盖式），不做多局管理/命名。
- 存档不跨设备、不导出；清浏览器数据即丢档（学习项目，不做云端）。
- 观战模式无"暂停/加速"控制，节奏固定 700ms/次 AI 决策。
- 回放拖动是"每次 input 都全量重演"，长局（数千步）拖动会略卡；未做"就近重演"
  的优化（原计划写进注释，实测百步级局无感知，故不做）。
- 观战模式下座次技能点亮只对锁定技生效（`seatSkillOn` 仍按原逻辑），不做全量
  技能状态可视化。
