# M14：势力维度与主公技——护驾 / 激将 / 救援

标准版 25 将里有三名主公（曹操/刘备/孙权）各带一个主公技，本项目此前完全没有
"势力"这一维度，主公技也无处安放（2026-10-06 定）。

1. **势力（Faction）**：新增 `GENERAL_FACTION`（魏/蜀/吴/群）与 `FACTION_NAMES`。
   势力是主公技的唯一消费方，不参与胜负或技能以外的任何规则。
2. **主公技作为第四类技能的第五种**：`SkillInfo.kind` 增加 `'lord'`。**关键约束：
   主公技只在持有者位于主公位时生效**——本作武将随机分配，曹操完全可能坐在反贼位
   （原版是"主公选将"，位置与技能绑定；本作必须显式判定 `identity === 'zhu'`，
   否则反贼曹操也能指挥魏势力，等于白送一个技能）。
3. **护驾（曹操）与激将（刘备）共用一套"求援三段式"**：主公被要求应答
   （出闪/出杀）时，若场上有同势力且**持有所需牌**的盟友，先开 `lordSkill` 询问
   主公是否求援；同意则逐个问盟友（`aidIds` 队列），盟友应允则由其出牌
   （`aidForId` 标记主公，日志 `respond.aid`），都不应则回退给主公自己。
   帧与询问状态不被修改——求援只是"谁来回这个询问"的换人，**规则后果完全归主公**
   （杀仍打向主公的目标、闪仍为主公挡刀）。
4. **救援（孙权）**：其他**吴势力**角色对主公使用【桃】时，主公额外回复 1 点。
   接在 `respondTao` 的成功分支上，条件含"孙权在主公位"。
5. **AI 立场化代打**：盟友是否应允，复用 M12 的 `inferLordFavor`——推断主公为敌
   （反贼视角、或立场分 ≥ 阈值）则拒绝；否则出牌（出闪优先真闪，出杀优先真杀）。
6. **UI**：`lordSkill` 询问分两种形态——主公视角是"求援 / 自己处理"，盟友视角是
   "打出【闪】/【杀】 / 不应"。

## 已知简化（记录在案）

- **激将的"使用"路径未接**：主公在出牌阶段主动使用【杀】时本可激将求援，本作只接
  了"打出"路径（南蛮/决斗/借刀等的应答）。理由：那需要在出牌阶段插入"先问主公
  是否激将、再选盟友、再选目标"的交互，收益（省一张杀）远低于复杂度；记录在案
  以防被当 bug。
- 护驾同理：闪只有"打出"没有"使用"，故护驾已完整。
- 主公技不询问真人以外的"是否愿意"以外的信息：AI 盟友只看立场分，不看自己手牌
  的余量（有一张闪就出）。
- 势力不显示在 UI 座次上（仅武将图鉴与主公技提示里可见）；原版座次显示势力色，
  本作不做（视觉层与规则层解耦，避免为装饰改动 `view`）。
- 主公技的求援对"主公自己也是唯一应答者"的情形（无同势力盟友）直接跳过，不产生
  额外询问。
