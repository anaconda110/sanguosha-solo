# ADR-0028：M24 确定性复盘报告——结构化报告、独立质检、按需渲染

参考文章把一次不可靠的大生成拆成可检查的小单元：每阶段中间产物落盘、同一数据源
渲染多种交付、独立质量检查拦截空模块与截断。M24 把这套流水线思想迁移到本项目的
终局复盘（2026-10-25 定），但不引入 LLM、网络或新的引擎语义。

## 决策一：seed + actionLog 是复盘唯一真相

报告输入只有 `seed / humanId / spectate / actionLog`。生成时从 `setup(seed)` 开始
重演完整动作日志，再从终局 `GameState.log` 汇总结果，不读取当前 UI 视图，也不保存
额外快照。报告内嵌深拷贝后的完整动作日志，因此结构化报告可自证“由哪些输入生成”。

报告不包含生成时间、随机 ID、浮点耗时等易变字段。同一输入的 JSON 与 Markdown
必须逐字节一致，便于回归测试、差分排查和后续归档。

报告契约包含：

- 对局结果：胜方、回合数、动作数、事件数、动作类型构成；
- 身份全貌：五名玩家的身份、武将、存活状态、最终体力/手牌/装备/判定区；
- 玩家计数：造成伤害、承受伤害/体力损失、回复、濒死、阵亡、击杀；
- 可观测触发：技能事件、装备/牌能力事件的次数与归属；
- 关键时间线：伤害、回复、濒死、阵亡、奖惩、无懈、判定、技能、能力、终局等事件，
  每条保留原 `state.log` 的一基索引与回合一基序号。

## 决策二：质检独立重演，错误阻断交付

报告生成和报告质检是两个步骤。`inspectReplayReport()` 会重新执行
`setup(seed) + actionLog`，并独立检查：

- 重演能否完整应用全部动作并到达终局；
- 报告胜方、回合数、动作数、事件数是否与重演一致；
- 五名玩家是否完整唯一，最终状态是否逐字段一致；
- 玩家伤害汇总、全局摘要、动作类型、技能/能力计数是否能从事件日志复算；
- 关键时间线的序号、回合与事件内容是否与 `state.log` 对应；
- 玩家视角的 `humanId` 与观战模式是否一致。

任一 error 级检查失败时，`createReplayArtifact()` 不生成 Markdown。warning 只提示
覆盖缺口，例如“本局没有可观测技能事件”，不会阻断交付。锁定技与部分用牌转换不发
`skill` 事件，因此报告明确称其为“可观测发动次数”，不根据结果反推虚构次数。

## 决策三：结构化报告是唯一渲染源

Markdown 渲染器只消费 `ReplayReport + ReplayQualityReport`，不再读取引擎状态。
浏览器组件只负责按需触发生成、预览、复制与下载 `.md`。将来增加 JSON、HTML 或
PDF 交付时，应复用同一报告契约，而不是重新解释事件。

报告在用户点击“查看复盘报告”时才生成，避免终局瞬间执行两次重演。UI 先绘制加载态，
再同步生成；当前百步级对局两次重演为百毫秒量级，若未来长局出现明显卡顿，可整体迁入
Web Worker，而不改变纯函数契约。

## 已知简化（记录在案）

- 报告验证的是“输入重演后可解释且内部一致”，不评价玩家策略是否最优，也不还原 AI
  的隐藏思考或蒙特卡洛采样过程。
- 技能/能力计数是日志可观测口径；锁定技和部分 use 类转换不会产生独立事件。
- 报告内嵌完整动作日志，长局体积会线性增长；当前只在内存中按需生成，未做报告归档槽位。
- 当前只提供 Markdown 下载与剪贴板复制，不提供 Word/PDF、分享链接或服务器存储。
- 质检通过不等于对局一定没有规则 bug；它守住报告契约与重演一致性，规则正确性仍由
  smoke/regression/构造局面测试负责。

## 验证

- `tests/review.test.ts`：终局报告生成、同输入 JSON/Markdown 逐字节稳定、玩家状态篡改
  拦截、终局后多余动作拒绝交付。
- `npm test`：新增用例与既有引擎/视图/持久化测试共同运行。
- `npm run typecheck`：报告类型、Vue 组件与浏览器导出代码统一检查。
