# M17：发布闭环与护栏封顶——CI、Pages、引导、六技能断言

M16 之后项目站在一个自然边界上：标准版内容齐了，但**测试资产没有被自动化保护**
（回归脚本只在本地跑）、**产物无处可玩**（dist 从未离开过本机）、**陌生人进不来**
（没有引导）。M17 一次补齐这三件事，外加在写断言时抓到的一个真 bug（2026-10-06 定）。

1. **修 bug：护驾/激将的触发条件写反了**。M14 初版只在"主公**自己有**闪/杀"时才
   开求援询问——而主公技的核心场景恰恰是"自己**没有**、等盟友救命"，那条路径
   直接判定命中。修复：`canShan || 有同势力可代打的盟友` 三处（杀帧、南蛮、万箭、
   决斗）全部改为"有闪/杀素材**或**有盟友可代打"才走直接结算。顺带修一处语义：
   无双的张数需求按"牌的归属者"（主公）取，而非代打的盟友。
2. **六技能断言补齐**（空城/马术/奇才/护驾/激将/救援）：此前 40 项技能只有 34 项
   有断言，这 6 项各补一个构造局面。**写测试抓到了第 1 条的 bug**——这是回归护栏
   价值的又一次实证。至此 40/40 全覆盖。
3. **CI（.github/workflows/ci.yml）**：push/PR 时自动跑 typecheck → smoke（120 局）
   → regression（40 局）→ build，构建产物上传 artifact。此前的护栏质量早已够
   上 CI，差的只是那个 yaml。
4. **GitHub Pages 部署（deploy.yml）**：push 到 main 自动构建并发布；vite `base`
   设为 `/sanguosha-solo/`（项目子路径）。**首次启用需在仓库 Settings → Pages 把
   Source 设为 "GitHub Actions"**（一次性手动步骤，无法由代码完成）。
5. **新手引导覆盖层**：首次进入显示五条要点（身份即胜利条件 / 点牌再点目标 /
   回合四阶段 / 应答看提示条 / 技能在座次卡上）+ 一条复盘提示（回放与 seed）。
   看过即写 localStorage 不再弹；隐私模式下每次显示（优雅降级）。

## 已知简化（记录在案）

- 存档单槽、不跨设备（M15 已记）。
- 引导是覆盖层而非分步教学局；"引导式第一回合"（高亮下一步该点什么）未做。
- Pages 部署的启用开关（Settings → Pages）在仓库设置里，代码无法代按；deploy
  workflow 在启用前会因权限失败一次，启用后自动恢复。
- CI 的 smoke 用默认 120 局（约 5–8 分钟），未做分片或缓存博弈——够用先跑。
